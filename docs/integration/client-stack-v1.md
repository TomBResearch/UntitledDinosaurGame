# Client stack v1 — what UDG-004 chose, and what it measured

Status: recorded by UDG-004 implementation on 2026-11-15. This is the write-up UDG-004's assignment
record §4.1 asks for (W-0): the client's dependency pins, the measurements behind them, the
typechecking layout, the development server's bind and port behaviour including the route from a
host outside the container, and the facts a later task inherits rather than re-derives.

It is a `docs/integration/` note, like [colyseus.md](colyseus.md) and [engines.md](engines.md). The
machine-readable half of the pin list is [dependencies.json](dependencies.json), regenerated by
`pnpm dependencies:record`; the normative half — what UDG-004 was *assigned* — is
[the assignment record](../contracts/assignments/UDG-004.md). Where this file says "measured", the
number came from a command on the listed date, not from a release note.

## 1. Pins, and the measurement behind each one

| Package | Pin | Licence | Why this version |
| --- | --- | --- | --- |
| `@babylonjs/core` | `8.56.2` | Apache-2.0 | The newest Babylon major that compiles cleanly under the repository's `skipLibCheck: false`. See §1.1. |
| `react`, `react-dom` | `19.3.1` | MIT | React 19 stable line; `@types/react` `19.3.0` and `@types/react-dom` `19.3.0` compile clean against it. |
| `@types/react`, `@types/react-dom` | `19.3.0` | MIT | Types only, in `apps/client`'s `devDependencies`. |
| `vite` | `8.3.6` | MIT | Already the root dev dependency from UDG-001; `@colyseus/tools` requires `^8.0.0`, so the client does not introduce a second Vite. |
| `@playwright/test` | `1.65.0` | Apache-2.0 | Unchanged from UDG-001. Its pinned Chromium build is `chromium-1254`. |

Deliberately absent:

- **`@babylonjs/loaders`** — no `.glb` import path exists in M0; the placeholder scene is built from
  Babylon primitives.
- **`@webgpu/types`** — disallowed by the assignment's pin rules, and measured not to be the answer
  anyway (§1.1).
- **`@colyseus/sdk` in `apps/client`** — [the UDG-004 contract](../contracts/UDG-004.md) forbids a
  transport dependency in the client; §5 explains why that is a real boundary rather than a formality.
- **`@vitejs/plugin-react`** — deferred. Vite 8's out-of-the-box pipeline transforms `.tsx` by
  esbuild, which is enough for the deliverable: HMR, Fast Refresh and automatic JSX are not on
  UDG-004's acceptance list, and adding a dependency that was measured to be unnecessary is a
  decision with a cost and no benefit in scope.

### 1.1 Why Babylon 8 and not 9 (measured, not assumed)

UDG's compiler policy is `skipLibCheck: false` repository-wide ([ADR 0002](../adr/adr-0002-strict-typescript-policy.md)
territory, established by UDG-001). Under that policy a package's *own* `.d.ts` files are compiled,
so a dependency's declaration hygiene becomes UDG's build problem.

Measured at `81a341f` with the pinned `24.22.2` toolchain, compiling a one-line module that imports
`Engine`, `Scene`, `ArcRotateCamera`, `Vector3`, `Color3`, `MeshBuilder`, `StandardMaterial` and
`Observable`:

| Candidate | Third-party declaration diagnostics | First-party errors |
| --- | --- | --- |
| `@babylonjs/core@9.36.0` | **154** | 0 |
| `@babylonjs/core@9.36.0` + `@webgpu/types` | 17 (conflicts, not silence) | 0 |
| `@babylonjs/core@8.56.2` | **0** | 0 |

Babylon 9's declarations reference WebGPU types and collide with Babylon's own vendored copies.
Adding `@webgpu/types` reduces the count and does not clear it, and the pin rules forbid the package
in any case. Adopting 9.x would therefore mean either weakening `skipLibCheck` repository-wide or
carrying an ignore list — both out of UDG-004's scope, and both decisions that belong to whoever
owns the compiler policy. **Babylon 9 is a deferred decision, not a rejection**: if UDG wants it,
the owner decides the `skipLibCheck` question first and the pin moves in a commit that says so.

### 1.2 What Babylon 8 brings that the code uses

`Engine`/`NullEngine`, `Scene`, `ArcRotateCamera`, `FreeCamera`, `Vector3`, `Color3`, `Color4`,
`MeshBuilder` (`CreateBox`, `CreateGround`, `CreateSphere`, `CreateLines`), `StandardMaterial`,
`Mesh`, `Observable`, `RenderTargetTexture`, `EngineStore`, `Logger`. All are reachable from
`@babylonjs/core`'s own entry points; the client never imports a deep path, so a Babylon upgrade
touches one import block rather than the rendering code.

## 2. Typechecking and lint layout

| Concern | Where | Notes |
| --- | --- | --- |
| Client source (`src/**/*.ts`, `src/**/*.tsx`) | `apps/client/tsconfig.json` (`jsx: react-jsx`, DOM lib) | `pnpm typecheck` → `pnpm --filter @udg/client typecheck`. |
| Client tooling sources (Vite config, dev-only harness) | `apps/client/tsconfig.tools.json` (`allowImportingTsExtensions`) | The dev harness imports Babylon from here; excluded from `pnpm build`. |
| Browser suite | `tsconfig.e2e.json` at the root, part of `pnpm typecheck:root` | `.tsx` under `tests/e2e` was already lint-scoped by the accepted ESLint config; the gap UDG-004 closed was **typechecking**, not linting. |
| `playwright.config.ts`, `vitest.config.ts`, `tools/**/*.ts`, `tests/unit|contracts|integration|runtime|reference/**` | root `tsconfig.json` | `tests/unit/udg-004/browser-results.ts` lives here so both Vitest and Playwright can import one definition of the artefact shapes. |
| ESLint | unchanged, byte-identical | Grant G-5 was withdrawn once measurement showed `.tsx` was already linted. A lint config change needs its own owner decision. |

`pnpm exec tsc -b --dry` reports no project references, so "every populated workspace project is
typechecked" means each `tsconfig` is invoked — which is what `pnpm typecheck` does.

## 3. The development server, measured

`pnpm dev` runs `vite` against `apps/client/vite.config.ts` with `clientMode: 'udg'`.

| Property | Measured value |
| --- | --- |
| Default bind | `127.0.0.1:5173`; the banner prints `Local:` only, no `Network:` line |
| Ready line | `[udg] UDG_CLIENT_READY server=ws://127.0.0.1:2567 client=http://127.0.0.1:5173/` |
| Second ready signal | `[udg] UDG_CLIENT_HARNESS=dev-only` — only when `UDG_DEV_HARNESS=1` |
| Server URL override | `VITE_UDG_SERVER_URL` (e.g. `ws://127.0.0.1:2567`) |
| Bind override | `UDG_DEV_HOST=0.0.0.0`, which also sets `strictPort: true` |
| With `UDG_DEV_HOST=0.0.0.0` | `Local: http://localhost:5173/` **and** `Network: http://172.18.0.2:5173/ eth0` |
| Port already taken | `Error: Port 5173 is already in use` and a non-zero exit, because `strictPort` is on |

The container case (Linux in Docker, reviewing from a Mac) was measured end to end on port 5173, and
`--network container:…` plus `-p` **does not work** — Docker registers the mapping on the container's
own network namespace, so nothing lands on the host. The route that works is the ordinary one:

```console
# inside the container
UDG_DEV_HOST=0.0.0.0 pnpm dev

# on the Docker host, restricted to the host's own loopback
docker run -it --rm --network host alpine/socat tcp-listen:5173,fork,reuseaddr tcp-connect:172.18.0.2:5173

# in Chrome on the Mac
http://127.0.0.1:5173/
```

Measured on this container: `curl http://127.0.0.1:5173/` → `200`, `curl http://172.18.0.2:5173/` →
`200`, and a second server on the same port refused by `strictPort`. `172.18.0.2` is this container's
address and will differ per host; `docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' <container>`
prints it.

**What the Mac check is for.** It is human inspection only, and it produces no evidence. GitHub-hosted
CI is the acceptance record, because CI is where the Playwright suite runs against the pinned Chromium
and writes retained artefacts. A preview that looks right on a Mac and was never run in CI proves
nothing about UDG-004's acceptance criteria.

## 4. The scene, and two things the code got wrong before it was measured

`apps/client/src/rendering/create-scene.ts` builds the placeholder: a ground, two axis arms, two end
caps, and a presentation marker per entity. Two facts a later task inherits:

**Scale: a Babylon unit is not a metre here.** The axis arms are 3 units on the positive side and
1.5 on the negative, while the shared `AXIS_SCALE_METRES` says 1 unit = 0.1 m — so the arms are 0.3 m
and 0.15 m in world terms, which is why they read as trim rather than as 3-metre rulers. Camera
distances, however, are in metres (`2`–`20`), so the scene reads as a small object on a large floor.
`presentedHeightUnits` is recorded in **units** (≈1.8) beside `axisScaleMetres` (0.1) and the arms'
metre values, so nothing has to guess which scale a number is in. `docs/integration/engines.md`
freezes the unit policy at Gate A; UDG-004 records the values and changes no policy.

**Handedness was broken and is now measured.** The negative axis arms were drawn at **+0.6** because
the mesh location double-negated an already-negative offset. It could not be seen from `getMetadata`,
because metadata described the intended placement rather than the rendered one. A new browser check
asks the render path: Babylon is told to pick only on the positive axis and then only on the negative,
and counts the hits. Five meshes agree (two +X arms, two −Z arms, ground); the two positive-Z caps and
the two negative-X arms are reported by `sweepUdgPicks` as misses, which is expected — they are caps
placed *past* the arm ends, and the sweep records both the marker positions and the sweep misses so a
reviewer sees what was actually checked. `axisMarkerWorldPositions` in the lifecycle artefact is the
machine-readable half; `handednessPicksAgreeing` and the two list fields are the honest half.

## 5. Connection state without a server

`apps/client/src/network/ClientConnection.ts` is a hand-written `WebSocket` wrapper. The UDG-004
contract forbids `@colyseus/*` in the client, and the reason is visible in the failure path: a Colyseus
client logs at the top of the console whenever it cannot reach a room, and UDG-004's acceptance list
requires an *unexplained* console error to fail the browser run. A transport that is chatty by default
would either flood the artefact or force an allow-list for its own noise. So the client owns the
transport, and a refused connection is a rendered state (`ConnectionStatus` shows `failed` plus a
retry affordance) rather than an exception.

The expected failure is declared, not ignored: the browser suite's allow-list matches
`WebSocket connection to 'ws://127.0.0.1:2567' failed` **and** the matching `Connection to … failed`,
with the URL taken from the same environment variable the client reads. Anything else — including a
Colyseus-style log appearing anyway — is counted and fails the run. `connectionState` in the artefact
is `failed` on a CI run with no server, and that value is what makes a real regression (a page that
crashes before connecting, say) distinguishable from the ordinary no-server state.

## 6. The development seam, and how it stays out of the build

`window.__udgClientHarness` is installed only when all three hold: Vite's `import.meta.env.DEV`, the
client mode is `udg`, and `UDG_DEV_HARNESS === '1'`. It exposes `mount`, `unmount`, `cycle`,
`snapshot`, `pick` and `sweep` — never a state-changing game lever. `ClientRuntime`'s public surface
stays `start`, `setPresentedPose`, `removePresentedEntity`, `dispose` plus one read-only `counters()`,
so the runtime does not grow a lifecycle API just because the tests would like one; the harness holds
the mount/unmount levers instead, and disposes the runtime rather than reusing a disposed one.

The one fact worth carrying forward is **how the seam leaked the first time**. Reading
`import.meta.env['VITE_UDG_SERVER_URL']` — bracket syntax — makes `import.meta.env` a *runtime*
object, which prevents Vite from constant-folding `import.meta.env.DEV` to `false` in a production
build. The harness was then statically reachable, and `dist/assets/lifecycleHarness-<hash>.js`
appeared in the shipped bundle even though it could never execute. Declaring the variable on
`ImportMetaEnv` and reading it with member syntax restored the folding. The contract suite now builds
the client for production inside the test (forcing `NODE_ENV=production`, because Vitest exports
`NODE_ENV=test`) and fails if `__udgClientHarness`, `installLifecycleHarness`, `lifecycleHarness` or
`sceneReadout` appears in any `dist` file **including source maps**, or if the harness is reachable
from the static module graph.

## 7. Browser evidence

`pnpm test:e2e -- --suite camera` starts the dev server through `playwright.config.ts`, runs seven
cases in headless Chromium and writes five kinds of artefact under `UDG_BROWSER_OUT` (default
`artifacts/.local/browser-evidence`):

| Artefact | Says |
| --- | --- |
| `camera-browser-results.json` | browser identity, the seven cases, the measurements, the screenshot list with hashes |
| `lifecycle-counts.json` | the ten mount/unmount cycles and every registry/loop/listener count after each |
| `console-errors.json` | every page and console error, split into expected and unexpected |
| `browser/screenshots.json` | the six screenshots with bytes and SHA-256 |
| `browser/*.png` | the pictures |

`tests/unit/udg-004/browser-results.ts` is the single definition of those shapes and the gate that
judges them; `tests/contracts/UDG-004.test.ts` applies it, and
`tests/unit/udg-004/evidence-gates.test.ts` proves each refusal by building a valid artefact set and
breaking it in exactly one way — the six demonstrations the assignment record §6.2 lists (E-1 to E-6).
One consequence of the same work reaches every task: `tools/checks/src/evidence.ts` now treats binary
artefacts as byte-transferred rather than as text, and refuses (without rewriting) a binary that
carries a machine path. See [the evidence requirements](../validation/evidence-requirements.md) and
§8 of the UDG-004 assignment record.

The suite reads Babylon's own registries (`Engine.Instances`, `EngineStore`, `Observable`) and counts
`requestAnimationFrame` calls in a window spy, so "no live game loop" is an external observation
rather than a number the runtime was asked to report about itself.

## 8. Commands

```console
pnpm install --frozen-lockfile
pnpm typecheck && pnpm lint && pnpm build && pnpm test
pnpm test:e2e -- --suite camera        # starts its own dev server; needs the pinned chromium
UDG_DEV_HOST=0.0.0.0 pnpm dev          # only when you mean to expose the dev server
pnpm test:e2e -- --suite netcode       # exits 1, naming UDG-SPIKE-001
pnpm test:e2e                          # exits 1, naming all five owners: no task owns "every suite"
```

In this container the pinned Chromium already lives at `/opt/playwright-browsers`; set
`PLAYWRIGHT_BROWSERS_PATH=/opt/playwright-browsers` and do **not** run `playwright install`, which
would fetch a second copy of the browser UDG-001 pinned. CI installs it with
`pnpm exec playwright install --with-deps chromium`.

## 9. Deferred, refused and still open

- **Babylon 9.x** — see §1.1. Needs an owner decision about `skipLibCheck` before a pin change.
- **`@vitejs/plugin-react`** — deferred with the reasons in §1; a later task may add it with its own
  measurement.
- **Pointer-event unification** — the camera's pointer path uses `pointerdown`/`pointermove`, not
  Babylon's `PointerInfo.sourceEvent`, because jsdom (the only DOM in `pnpm test`) synthesises no
  `pointerType` or `pointerId`. The mouse is therefore driven through pointer events and touch through
  touch events, with the mapping types and ports frozen in `camera-math.ts`.
- **`scene.getEngine()` typing in the harness** — the strict project resolves the global `Engine`
  declaration against Babylon's own, which declares no `getScene`; the seam casts the engine rather
  than lying to the compiler.
- **`D-004-15`** — screenshot freshness and integrity are gated by UDG-004's own suites; the shared
  vector-manifest schema is unchanged. The owner may still move those checks into the shared gate,
  which is a change to `tools/checks/src/evidence.ts` and not to this file.
- **`D4`** — durable evidence storage stays open and undesignated; UDG-004 provisions nothing.
