# Colyseus 0.18 public API map (UDG-003 Phase 0)

Status: **Phase 0 record, provisional.** Every pin below is an *installed candidate* approved as a
provisional set under owner decision **D-2**, not a compatibility endorsement. Compatibility claims
come only from the probes in this table. [colyseus.md](colyseus.md) 6.1 sets the row format;
[UDG-003-phase-0.md](../contracts/assignments/UDG-003-phase-0.md) sets the scope;
[UDG-003-readiness-proposal.md](../contracts/assignments/UDG-003-readiness-proposal.md) 2.4 sets the
probe ids.

Two blockers are open and gate Phase 1:

- **PH0-B1** — the pinned declarations do not typecheck under the repository compiler policy. See
  [§5](#5-blocker-ph0-b1-third-party-declarations-do-not-typecheck).
- **PH0-B2** — the pinned set has no epoch concept at all, so epoch renewal is application work.
  This is a design consequence rather than a defect, and it is recorded here because the readiness
  proposal assumed a probe answer either way.

## 4. PR-8: what the acknowledgement actually tracks (D-7 evidence)

Five scenarios, one room, loopback, recorded in
`apps/server/probes/pr8-ack.probe.ts`:

| Scenario | Observed |
| --- | --- |
| S1 three frames sent, none consumed | `clientSent 3`, `pending 3`, server `consumedCount 0`, client `lastProcessed 0` |
| S2 one frame consumed | server `1`, client `lastProcessed 1` |
| S3 one frame consumed then **refused** by the application | refusal recorded, server `1`, client `lastProcessed 1` |
| S4 `bufferMaxSize 2` with 6 frames sent | buffer held 2, server `consumedCount 4`, client `lastProcessed 4`, dropped frames never acknowledged |
| S5 synthesised idle frame | `wasIdle true`, server `0 → 0`, client `0 → 0` |

The pinned acknowledgement therefore separates *received* from *consumed*, and does **not** separate
*consumed* from *applied*. A frame the game refuses is indistinguishable, from the client's seat,
from a frame that moved a dinosaur. There is no public API to withhold or retract an acknowledgement.

That is the whole of what PR-8 can answer. **D-7 stays open**: the prohibition "never acknowledge a
frame that was never represented in state" is not waived here, and the consequence recorded by the
probe is that an application-level journal — not this counter — would have to carry it.

## 5. Blocker PH0-B1: third-party declarations do not typecheck

`pnpm --filter @udg/server typecheck:probes` (that is `tsc -p tsconfig.probes.json --noEmit`, which
inherits `tsconfig.base.json` unchanged) exits non-zero with **27 diagnostics, none in repository
code**:

| Declaration file | Code | Count | Cause |
| --- | --- | --- | --- |
| `@colyseus/better-call@1.3.3/dist/context.d.mts` | `TS2304` | 18 | references `HeadersInit` |
| `@colyseus/better-call@1.3.3/dist/endpoint.d.mts` | `TS2304` | 1 | references `HeadersInit` |
| `@colyseus/better-call@1.3.3/dist/error.d.mts` | `TS2304` | 3 | references `HeadersInit` |
| `@colyseus/sdk@0.18.9/build/HTTP.d.ts` | `TS2304` | 1 | references `HeadersInit` |
| `@colyseus/sdk@0.18.9/build/HTTP.d.ts` | `TS2344` | 2 | a generic constraint its own declaration does not satisfy under TypeScript 5.9.3 |
| `@colyseus/core@0.18.27/build/router/node.d.ts` | `TS1192` | 1 | `import type http from 'http'` needs `allowSyntheticDefaultImports` |
| `@colyseus/ws-transport@0.18.4/build/WebSocketTransport.d.ts` | `TS1192` | 1 | same |

Adding the missing type packages (`@types/express`, `@types/debug`) removed every `TS7016` and is not
a policy change; what remains has three causes, and every remedy is a decision the owner owns:

1. **DOM globals.** `lib: ["ES2024"]` is deliberate for a Node workspace, and UDG-001 forbids the DOM
   library outside `@udg/client`. Loading `lib: ["DOM"]`, or hand-declaring `HeadersInit`, is either a
   policy widening or a shim that hides an incompatibility.
2. **`esModuleInterop: false`.** The libraries default-import `node:http` in their own declarations.
   `allowSyntheticDefaultImports` would silence it; the adopted policy says no.
3. **A declaration bug** in `@colyseus/sdk` that no flag other than `skipLibCheck` (forbidden) or a
   version change can address.

`tests/contracts/UDG-003.test.ts` pins this inventory in both directions: it fails if a diagnostic
appears, and fails if one disappears or moves, so the blocker cannot be quietly widened away and
cannot silently change shape when the pins move. Phase 1 does not start on top of it.

Because emit is still possible, the probe build uses `tsc --noCheck`
(`pnpm --filter @udg/server build:probes`) to obtain runnable JavaScript while PH0-B1 is open. The
flag is on the command line, never in a config file, and the suite asserts that split.

## 6. Supply-chain posture

`pnpm-workspace.yaml` denies dependency build scripts, and pnpm 12 enforces that with
`ERR_PNPM_IGNORED_BUILDS` rather than a warning. `msgpackr-extract@3.0.7` — pulled transitively by the
D-2 pin set — is denied by name (`allowBuilds: msgpackr-extract: false`), so **no dependency build
script runs in this repository** and `msgpackr` uses its pure-JavaScript decoder. PR-1 asserts the
denial by name. Letting the native addon build is a separate owner decision (amendment A-11 in the
Phase 0 assignment), and would need its own evidence.

## 7. What Phase 0 did not establish

- Nothing about prediction, rollback or client reconciliation. `@colyseus/sdk` is present only as a
  transport smoke client under **D-3**; UDG-SPIKE-001 owns prediction validation.
- Nothing about replication timing, client-side interpolation, or behaviour under loss, latency,
  reconnection under load, or multiple processes.
- Nothing about `@colyseus/testing` (unselected) or any transport other than `ws-transport`.
- No gate. Gate A stays **Not Run**, encoding widths stay provisional under ADR 0001, and the pins in
  [§1](#1-installed-set) stay candidates until the owner resolves PH0-B1.
