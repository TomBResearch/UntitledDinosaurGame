## Task contract

### Objective and prerequisites

Provide equivalent desktop and mobile intentions without implementing a second sender or movement system. Requires Verified 004 and 005 and adopted P09. Navigation can be a test double until 007 is Verified. All input adapters feed one shared intent sampler; only the networking adapter sends fixed-step frames.

### Owned files and interfaces

Create apps/client/src/input/{InputIntentController,KeyboardAdapter,PointerAdapter,TouchAdapter,VirtualJoystick,world-direction,focus-policy}.ts; src/ui/{VirtualJoystickView,DestinationMarker}.tsx; tests/unit/input/{mapping,generations,touch,focus}.test.ts; tests/contracts/UDG-008.test.ts; tests/fixtures/input/parity.json; and tests/e2e/input.spec.ts.

InputIntentController exports sampleDirect(): Readonly<DirectFrame>, requestMoveTo(destination: Vec3): MoveToWire, requestCancel(): CancelPathWire, bindEpoch(epoch: number): void, clearOnBlur(): void and dispose(): void. It owns only local intent generation and request IDs; it cannot assign server ticks, route revisions or positions. requestMoveTo returns a command to the network adapter, while a local provisional marker is owned by UI. The controller starts neutral after bindEpoch and cannot sample active input before authoritative adoption is signalled by the network layer.

### Required input behaviour

Keyboard W/S and A/D cancel opposites; world-space direction derives from the camera's horizontal forward/right axes, normalised after combination. If the camera forward projects to near zero, preserve the last valid horizontal basis. Mobile joystick uses a radial dead zone 0.15 of radius and rescales the remaining radius linearly to [0,1]. Clamp at unit length. Pure fixtures provide explicit basis vectors so expected results do not depend on browser trigonometry.

Direct start increments generation once when a nonzero direct intention overrides idle/path/pending. Held input and release retain generation. New clicks/taps and explicit cancel increment it. Desktop mouse click and mobile tap ray-pick the same walkable source geometry; screen coordinates never enter the movement protocol. A tap is at most 250 ms and 8 CSS pixels displacement. Longer/larger gestures orbit or pan as configured; pinch and a captured joystick pointer cannot also create a destination. Events consumed by UI must not generate movement. Multi-touch tracks stable pointer IDs and handles pointercancel/lost capture.

Blur, hidden document and pointer loss clear held vectors immediately; clearOnBlur produces a zero direct sample for an active direct intention and cancels pending local gesture state. The next network sample is neutral. Do not depend on keyup arriving after blur. The camera may keep its pose but must not keep authoring movement. On disconnect or epoch change, flush local held/queued commands and destination markers, then wait for adoption before new prediction.

### Tests and acceptance

Run root checks, pnpm test:contract -- --task UDG-008 and pnpm test:e2e -- --suite input. I01-I08 must prove world-space parity within 0.000001 per axis. Test diagonal normalisation, camera basis rotation, joystick dead-zone boundary and max throw, tap versus drag/pinch, UI overlap, pointercancel, blur with W held, release while reconnecting, rapid click/direct alternation and request-ID uniqueness. Assert one intent generation per meaningful transition and one fixed-step sender registration regardless of active adapter.

Pass when all desktop and touch cases produce expected DirectFrame or command records and none directly mutates canonical state, camera or prediction history. Evidence includes sampled-intents.jsonl, parity-results.json, event-routing.json, generation-transitions.json and browser screenshots for joystick/UI interaction. Browser touch emulation proves adapter semantics only; actual mobile hardware performance belongs to later work.
