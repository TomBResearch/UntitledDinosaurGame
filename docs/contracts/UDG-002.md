## Task contract

### Objective and prerequisites

Freeze shared domain declarations and a validated protocol skeleton before a room consumes it. Requires Verified 001 and P02 adoption. This task owns types and validation, not movement or SDK prediction behaviour. Initial schema definitions remain Gate A candidates until actual two-client encode/decode validation.

### Owned files

Create packages/protocol/src/domain/{primitives,state,movement,commands,physics,navigation,wire}.ts; src/schema/{DirectInputSchema,PlayerSchema,RegionSchema}.ts; src/validation/{direct,commands,join,common}.ts; src/mapping/{to-replica,from-replica}.ts; src/{version,index}.ts; packages/config/src/{movement,network,limits,region,index}.ts; tests/contracts/UDG-002.test.ts; tests/fixtures/protocol/{valid,malformed,ordering}.json; and docs/contracts/protocol-v1.md. Changes to protocol/config manifests and exports are controlled-file edits.

### Interfaces and implementation requirements

Implement all declarations in [canonical domain declarations](../interfaces/domain.md) and the wire/result additions in [section 4](../interfaces/README.md). Export validateDirectFrame, validateMoveTo, validateCancelPath and validateJoin with Validation<T> results. Plain object domain validation precedes any use of coordinates, allocation or navigation admission. Field shape and identity are explicit. Wire projection flattens MovementIntentStamp into sessionEpoch and generation. Map every replica field bidirectionally; route points remain server-only. Define stable hash canonicalisation for config: UTF-8, sorted object keys, array order preserved, finite JSON values and SHA-256.

Schema encode/decode fixtures must include a minimal room-free round trip using pinned schema declarations, preserving all scalar state and sentinels. Document enum encoding, null-to-zero route sentinel, integer bounds, precision and version mismatch rejection. Do not add a client-owned authoritative transform setter. Version protocol incompatibilities explicitly; adding optional fields requires an agreed compatibility rule, not optimistic acceptance.

### Tests and measurable acceptance

Run the four root commands, pnpm test:fixtures and pnpm test:contract -- --task UDG-002. All protocol fixtures P01-P20 must have expected error codes. Test finite boundaries, +/-1 axes, diagonal normalisation, missing/unknown keys, malformed vectors, Unicode and oversized IDs, negative/fractional/unsafe integers, uint32 boundaries, null sentinels and round-trip verticalVelocity. Test config unit consistency and changed configHash on a single parameter change. A source fixture mutation must not mutate a validated readonly result.

Pass only if every public export compiles from its supported package entry point, all negative fixtures fail safely, domain entry points import no schema runtime and mapping preserves the complete prediction-relevant scalar set. Evidence includes protocol-field-map.json, roundtrip-results.json, rejection-results.json, config-hashes.json and root check logs. Schema constructor uncertainty is escalated to the networking owner; never fabricate an API or weaken validation to make a sample compile.
