## Task contract

### Objective and prerequisites

Implement the single collision owner and a testable scalar-adoption lifecycle. Requires Verified 005 and P07 adoption. The first candidate is a standalone upright capsule with Rapier character controller. Do not add moving platforms, dynamic impulses, rigid-body pushing or render-frame physics.

### Owned files and interfaces

Create packages/physics/src/{index,create-physics-world,RapierCharacterPhysics,collision-groups,world-config,scalar-adoption}.ts; tests/probes/rapier-character.probe.ts; tests/unit/physics/{controller,lifecycle,adoption}.test.ts; tests/contracts/UDG-006.test.ts; tests/fixtures/physics/{geometry,replay}.json; and docs/integration/rapier-adapter.md. Package/lockfile edits pin the exact Rapier dependency and binary identity under maintainer review.

Implement CharacterPhysics exactly. createCharacter rejects duplicate IDs and invalid dimensions, builds radius 0.35 m and cylindrical half-height 0.55 m from total height, and owns all collider handles. resolveMovement reseeds collider pose from canonical state, updates query data using the validated public procedure, calculates permitted displacement, applies the result once and reads grounded/pose state before returning. It never integrates horizontal velocity again through a competing world step. adoptAuthoritativeState restores all relevant scalars and query-visible pose before any replay call.

The physics world contains static geometry and characters only. Static geometry is created in stable source-ID order. Player locomotion filters exclude all player colliders and include marked solid terrain; validate the filter on the character-controller query as well as collision group storage. Upright yaw is not used to rotate the capsule away from Y. Store the controller's mutable query output only until read; sharing a controller across entities is allowed only if no transient result leaks into another entity's resolution.

Define resource accounting for worlds, controllers, colliders and optional bodies. removeCharacter is idempotent for a known removed ID; resolve/adopt for a missing ID throws a typed missing-character error without allocating. dispose is idempotent and frees all engine resources. No call after dispose except repeated dispose is allowed. Retain the stopped collider during the reconnect grace window; final expiry removes it once.

### Tests and acceptance

Run root checks, pnpm test:contract -- --task UDG-006 and pnpm test:e2e -- --suite physics. Test F01-F16 where applicable, including wall blocking, sliding around a corner, slope thresholds, supported step width, over-height rejection, descending snap, falls without jump, player overlap and both entity insertion orders. Ground-snap discontinuities must remain within configured limits and be labelled in traces.

Force adoption into a grounded state, a slope contact and an airborne vertical state, then replay identical input suffixes. Canonical/collider discrepancy must remain within 0.00001 m and penetration within 0.02 m; never cross the wall. After 1000 create/remove cycles, owned object counts return exactly to baseline. Report heap/WASM trends as supporting diagnostics, not proof of native cleanup by themselves. Pass only if the public probe compiles and deterministic lifecycle assertions hold. Evidence includes adapter-api-map.md, controller-config.json, binary-hashes.json, contact-traces.jsonl and resource-counts.csv. Representation approval waits for Gate B.
