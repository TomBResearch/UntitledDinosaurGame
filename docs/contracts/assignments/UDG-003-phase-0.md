## 2. Objective (Phase 0)

Establish, by **installing and executing**, whether the provisional pin set is usable and what its
public API actually is — before any authority or room behaviour is written. Deliver the API map with
honest results and the exact resolved dependency graph. A failed probe is a **result**, and the
correct output of this phase.

In scope — probe ids from [readiness §2.4](UDG-003-readiness-proposal.md#24-probe-plan-one-row-per-api-in-docsintegrationcolyseus-018-api-mapmd):

| Probe | Question Phase 0 must answer | Consequence of failure |
| --- | --- | --- |
| PR-0 | Does the pinned stack typecheck under this repository's compiler policy (`skipLibCheck: false`, no `any`, no `@ts-ignore`, no private `@colyseus/*/build/…` path)? | **Stop.** Escalate as a pin-set failure (D-2). The compiler policy is not relaxed and no `any` escape hatch is added |
| PR-1 | What exactly resolved: versions, one or two `@colyseus/schema` copies, peer and `express` resolution, licences? | Stop: the register cannot describe the graph |
| PR-2 | Is there a declared public fixed-step facility that ticks at the configured 20 Hz with the advertised `dt`? | **Gate A blocker** — record and escalate. No private or hand-rolled loop substitute is permitted |
| PR-3 | Is `DirectInputSchema` accepted as the fixed-input declaration, and do all five fields survive a real send/receive? | Blocker for the input path — escalate |
| PR-8 | What does the public acknowledgement surface actually track: frames received, or frames applied? Experiment required, not inferred from a counter | Record with experiment output and **escalate for D-7**. Never restated as satisfied |
| PR-12 | Is the epoch-renewal procedure public and usable (needed later by `RESYNC_REQUIRED` and generation exhaustion)? | Record **BLOCKED** honestly. Inventing a reset call is forbidden |

Also in Phase 0: the probe build configuration (workspace-local probe project, separate typecheck and

## 4. Hard stops

1. **Probes before behaviour.** No room, adapter or authority code may exist before the probes report.
   A probe that fails after behaviour was written means the behaviour was designed on an assumption.
2. **No fake evidence.** A probe may not be satisfied by a cast, `@ts-expect-error`, `any`, a private
   path (`@colyseus/core/build/…`, reachable through the `./*` export wildcard and therefore forbidden),
   or a hand-written stand-in for SDK behaviour. An API absent from the installed declarations is a
   **failed probe**, per [colyseus.md](../integration/colyseus.md).
3. **No silent pin drift.** Exact versions only, no ranges, no `pnpm.overrides`, no patched packages.
   What resolves is what gets recorded, including where it differs from §2.1's proposed values.
4. **D-7 is not pre-approved.** PR-8 returns an experiment, not a counter, and nothing is waived.
5. **Compiler policy is invariant.** `skipLibCheck: false`, `strict`, `noImplicitOverride`,
   `exactOptionalPropertyTypes` and the rest of `tsconfig.base.json` apply to the probe project too.
6. **Existing regressions stay green.** UDG-001 and UDG-002 remain Verified: their suites pass at the
   new head, every retained bundle still verifies, and no recorded byte or digest is rewritten.
7. **Retention: no new storage objects.** For this assignment: **do not create, delete or replace any
   GitHub release, tag, archive or storage location.** Evidence is retained append-only in the existing
   store; the releases created earlier remain reported as they are, and the audit snapshots are
   preserved. Owner decision D4 (an independent backup destination) stays open, and these releases do
   not close it.
8. **No gate claims.** Gates A, B and C remain Not Run. Reporting PR-2 as a blocker is not the same as
   passing Gate A, and PR-8 output is not a D-7 decision.
