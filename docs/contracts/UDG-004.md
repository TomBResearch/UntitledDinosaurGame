## Task contract

### Objective and prerequisites

Create a minimal browser-accessible Babylon.js greybox with React status UI and an orbit/zoom camera. Requires Verified 001. It may use a local test pose until 003 is ready. It must not introduce a competing movement controller or assume production networking. Camera/render state remains presentation-only.

### Owned files and interfaces

Create apps/client/{index.html,vite.config.ts}; src/{main.tsx,App.tsx}; src/rendering/{create-scene,PlayerView,OrbitCamera}.ts; src/ui/{ConnectionStatus,DevelopmentOverlay}.tsx; src/game/ClientRuntime.ts; src/network/ClientConnection.ts; tests/contracts/UDG-004.test.ts; and tests/e2e/camera.spec.ts. ClientRuntime exposes start(canvas: HTMLCanvasElement), setPresentedPose(entityId, pose), removePresentedEntity(entityId) and dispose(). Pose is readonly {position: Vec3; yaw: number}. No method writes authoritative state.

Configure the scene right-handed, Y-up and metres before adding geometry. The plane uses an asymmetrical axis marker to detect handedness errors. Camera orbit, pinch/wheel zoom and target follow are bounded; proposed radius limits are 2 to 20 m and elevation 10 to 80 degrees. Camera consumes pointer gestures only outside active UI regions. Keep mesh ownership and scene disposal explicit. React renders status and debug controls; the renderer owns the animation loop exactly once.

### Tests and acceptance

Run root checks, pnpm test:contract -- --task UDG-004 and pnpm test:e2e -- --suite camera. Verify one canvas and one loop; correct right-handed axis marker; orbit/zoom clamping; aspect resize; focus loss; touch rotation/pinch; UI input exclusion; visible connection failure; ten mount/unmount cycles; and removal of meshes, observers, event listeners and WebGL resources. Blocked pointer events and failed asset load must not crash the UI.

Pass when the browser smoke test renders the greybox and two independent presented entities, camera operations never mutate either pose, and disposal leaves no live game loop or listener registered by the app. Evidence includes camera-browser-results.json, screenshots at orbit/zoom bounds, lifecycle-counts.json and console-errors.json. These screenshots prove basic behaviour, not later desktop/mobile frame-time budgets. Browser emulation may test event mapping but cannot certify physical-device performance.
