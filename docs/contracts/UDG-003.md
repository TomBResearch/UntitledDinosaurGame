## Task contract

### Objective and prerequisites

Build the minimal Colyseus authority reference for Gate A, with neutral-input and abuse safety. Requires Verified 002, adopted P03 and the pinned candidate server/SDK/schema set. The flat direct step is a spike reference under tests/reference/, not the final UDG-005 locomotion implementation. No physics, Recast, persistence or production identity service belongs here.

### Owned files

Create apps/server/src/{main,server-config}.ts; src/rooms/RegionRoom.ts; src/network/{ColyseusInputAdapter,join-validation}.ts; src/movement/MovementAuthorityAdapter.ts; src/state/map-player.ts; src/lifecycle/DevelopmentSessions.ts; src/telemetry/tick-metrics.ts; tests/reference/flat-direct-step.ts; tests/probes/colyseus-server.probe.ts; tests/contracts/UDG-003.test.ts; and docs/integration/colyseus-0.18-api-map.md. Patches to protocol schemas need protocol-owner review and must preserve 002 tests.

### Behaviour and interfaces

The adapter maps supported SDK input access to a UDG observation record containing optional DirectFrame, SDK identity/ack diagnostics and an idle flag. Its public consumeOne(entityId, serverTick) returns either one frame observation or neutral, never a list to be stepped repeatedly. registerSession and stopSession manage association to server-owned entity/epoch. Concrete SDK hooks are discovered through the compile probe and listed in the API map.

Set one fixed-step owner at 20 Hz and one 100 ms patch schedule using validated APIs. Stable entity iteration and tick cutoff follow [section 5](../interfaces/movement-authority.md). Accept at most one direct frame per tick, with neutral on empty. Initially discrete path requests receive NAVIGATION_BUSY and cannot mutate a route. Maintain a server-assigned development identity, epoch and transform; bind all movement to the authenticated development session association. Block incompatible join versions/hashes, disallowed origins and unconfigured non-loopback bind. An offender's malformed message must not crash the room or affect the observer.

Proposed abuse limits are application message payload 1024 bytes, 64 queued discrete operations per room, eight per entity, and continuous input admission at 40 frames/second with burst 40. For a transport or SDK buffer that cannot safely enforce that early, the owner must document the supported equivalent and prove bounded memory before acceptance. No private SDK counter manipulation is allowed.

### Tests and acceptance

Run root checks and pnpm test:contract -- --task UDG-003. Use a controllable tick scheduler for unit/integration tests and a real server smoke run. Test 100-frame burst versus exactly one entity step per tick; missing input; diagonal speed; invalid direct sample; old epoch; unknown message; join failure; observer survival; deterministic iteration; room disposal; and buffer cap under sustained abuse. The canonical flat position must never be set from a client message.

Pass only if 200 valid direct ticks produce the specified 40 m trace, neutral stops horizontal movement on the next tick, burst count cannot increase travel and the server probe compiles without any or private SDK access. Evidence includes ticks.jsonl, inputs.jsonl, buffer-depth.csv, abuse-results.json, api-map.md and room-lifecycle.json. Any absent required public fixed-step facility blocks Gate A; it does not authorise an alternative loop.
